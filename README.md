# 英雄联盟知识问答智能体（混合知识库 RAG 实践）

一个用于**学习 AI 应用架构**的可运行项目：用三种不同的知识库回答三类不同的问题，
并且每条回答都能溯源。

---

## 一、核心结论：知识库不是"选一个"，而是"分三类"

这是本项目最想讲清楚的一件事。英雄联盟的知识天然分成三类，存储方式必须不同：

| 知识类型 | 例子 | 存储 | 为什么 |
| --- | --- | --- | --- |
| **数值 / 事实** | 亚索 W 冷却多少、无尽之刃多少钱 | **SQLite**（结构化表） | 向量检索对数字不敏感，会给出"近似但错误"的答案；结构化查询 100% 准确 |
| **经验 / 策略** | 上单诺手怎么对线、谁克制亚索 | **Chroma**（向量库） | 语义模糊，没有唯一正确答案，只有相似度召回能命中 |
| **最新改动** | 这版本亚索加强了吗 | **联网搜索** | 本地库天然滞后，只能实时获取 |

**如果只建一个向量库，问数值时一定会出错。** 这就是"知识库选择的讲究"。

架构图：

```
用户提问
   │
   ▼
Router 路由分类 ──┬─ 数值  ─→ SQLite 参数化查询（官方 Data Dragon 数据）
                  ├─ 策略  ─→ Chroma 向量检索（攻略文档切片）
                  └─ 最新  ─→ 联网搜索兜底
   │
   ▼
上下文合并 → 大模型组织语言（只能使用检索到的内容）→ 回答 + 来源引用
```

关键保障：**模型不负责提供数值，只负责把查到的真实数据组织成人话。**
从工程上根除"一本正经地编数值"。

## 二、四步跑起来

> 前置：Python 3.9+（本项目在 3.13 上验证通过）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # 编辑 .env 填入你的模型 Key（可选，见下）
python check_models.py    # 先验一遍模型是否真的能调通，避免后面排查
```

> 默认配置：嵌入用「百度千帆上的千问 `qwen3-embedding-0.6b`」，生成用「DeepSeek `deepseek-flash`」。
> 千帆的**模型名必须全小写**，写成 `Qwen3-Embedding-0.6B` 会返回 `no_such_model`。
> 千帆的向量接口是 `/v2/embeddings`，**不是** `/v2/chat/completions`。

### 第 1 步：采官方数据（不需要任何 Key）

```bash
python ingest_data.py
```

拉取拳头官方 Data Dragon 的中文数据写入 `data/lol.db`：173 个英雄、866 件装备、
62 个符文、34 个召唤师技能，全部带版本号。

### 第 2 步：把攻略文档建成向量库

```bash
python build_kb.py          # 首次构建
python build_kb.py --rebuild   # 换嵌入模型 / 改切片策略后必须重建
```

默认会索引 `data/raw/docs/` 下的 4 篇示例攻略。把你自己的攻略放进该目录即可扩充。

### 第 3 步：提问

```bash
python ask.py "亚索 W 技能的冷却时间是多少？"
python ask.py "上单诺手对线应该怎么打？"
python ask.py --health      # 查看三层知识库状态
```

浏览器界面：

```bash
python app.py              # 打开 http://127.0.0.1:7860
```

### 第 4 步：跑评测

```bash
python eval/run_eval.py --save
```

输出路由准确率、关键词命中率、联网触发率，以及一份 badcase 清单用于归因分析。

## 三、关于 API Key（没有也能跑）

| 配置 | 没有会怎样 |
| --- | --- |
| `LLM_API_KEY` | 降级为「仅检索」模式：直接展示检索到的原始资料，不生成自然语言答案 |
| `EMBED_API_KEY` | 降级为离线哈希向量（只匹配字面重合，**效果很差**，仅供跑通流程） |
| `SEARCH_API_KEY` | 跳过联网兜底，只答本地知识库覆盖的内容 |

三个都配齐，才是完整体验。`.env` 里改 `LLM_BASE_URL` / `EMBED_BASE_URL` 就能换厂商
（DeepSeek / 通义 / 智谱 / OpenAI 都是 OpenAI 兼容协议）。

## 五、几个值得记住的设计细节

1. **数值不走 Text-to-SQL**。让模型写 SQL 既不稳定又有注入风险。这里改成
   "模型只抽取实体和字段 → 代码做参数化查询 → 结果回填给模型组织语言"。
2. **切片按语义边界切**。优先用 Markdown 标题切，超长段落才退化成滑窗切分，
   且保留 overlap。切片是 RAG 效果的第一杀手，比换模型影响还大。
3. **每个切片都带元数据**（英雄 / 分路 / 版本 / 出处）。检索时先按元数据过滤
   再做相似度，能显著减少"张冠李戴"。
4. **换嵌入模型必须重建索引**。向量空间变了，新旧向量混检结果不可信 ——
   `build_kb.py` 会自动做一致性校验并拒绝增量构建。
5. **联网触发要保守**。只在命中时效性关键词、本地检索为空、或相似度低于阈值时才联网，
   并且结果会本地缓存 24 小时，避免重复计费。
6. **检索不到就如实说**。系统提示里硬性禁止凭记忆补全；这比"硬编一个像样的答案"重要得多。

## 六、接下来可以做的优化（进阶路线）

- [ ] 接入 **Rerank 模型**：先粗召回 20 条再精排 top4，准确率通常有明显提升
- [ ] **混合检索**：向量检索 + BM25 关键词检索双路召回，互补
- [ ] **查询改写**：把"他 W 几秒"改写成"亚索 W 技能冷却时间"再检索
- [ ] **父子块（small-to-big）**：用小切片召回、用大切片喂给模型，兼顾精度与上下文
- [ ] **用户反馈闭环**：界面加点赞/点踩，把 badcase 自动回流成新的评测用例
- [ ] **知识运营**：给文档加"更新时间"字段，过期知识自动降权
